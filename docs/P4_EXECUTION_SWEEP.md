# SideDeck P4 Saxo SIM execution sweep

**Status: NO-GO — prepared for controlled SIM order approval, but no order was submitted.**

This batch adds one coherent, disabled-by-default execution boundary for the
SOFI one-share SIM candidate. It does not enable unattended execution, contact
Saxo, read credentials, or mutate an existing portfolio database.

## Implemented

- `application.saxo_market_data`: provider-neutral USD quote and EUR/USD FX
  evidence with UTC cutoff, freshness, regular-session, direction and cost
  checks. Evidence has an explicit `SYNTHETIC_FIXTURE` versus
  `AUTHENTICATED_PROVIDER` origin; synthetic values cannot pass submission
  preparation. Providers are injected; Yahoo and implicit provider fallback
  are not used.
- `application.saxo_execution_history`: bounded account/order/reference-scoped
  pagination and strict Fill/FinalFill parsing. Placement, working, cancellation
  and rejection records never become fills. Execution IDs are required and
  duplicate IDs or identity mismatches fail closed. Price and fee currencies
  are explicit input metadata; the parser does not infer EUR from an EUR
  account. Saxo's audit contract exposes `FillAmount`, `ExecutionPrice`, and
  `AveragePrice`/order-activity fields, while account-currency cost details are
  separate precheck/account evidence.
- `application.saxo_sim_submission`: fixed SIM-only SOFI one-share request
  shape, fresh successful precheck, EUR and USD risk limits, exact-payload
  operator approval through a trusted attestation verifier, durable
  single-consumption authorization, uncertain-outcome handling, and an
  explicit disabled-by-default transport boundary.
- `application.saxo_execution_pipeline`: EUR-to-USD conversion using the
  validated FX snapshot only for explicitly EUR-denominated fees, correct
  portfolio/account/reference matching, versioned durable pending-event
  recovery, deterministic replay-safe event identity, external execution
  deduplication, ledger fill posting and lifecycle update.
- `infrastructure.saxo_submit_transport`: strict SIM-host POST adapter with
  exact SOFI payload validation, bounded timeout, redacted errors, no redirect
  and no retry. It is disabled unless explicitly constructed for a separately
  approved test.
- `application.saxo_p4_acceptance --offline`: a credential-free final check
  that reports the remaining external gates without making a request.

## Evidence separation

The previously reported SIM account, instrument, precheck and zero-exposure
observations are owner-provided historical evidence. They were not re-requested
by this batch and do not prove a fill. The new tests use synthetic broker
responses only. No external quote, FX, order acknowledgement or execution
record was generated by the test suite.

The official Saxo contract distinguishes `EstimatedTotalCost` (instrument
currency), `EstimatedTotalCostInAccountCurrency` (account currency), and the
instrument-to-account conversion rate. The official order-activity contract
provides fill amount and execution price for fill events. If a live audit
response does not provide a fee in a known currency, SideDeck rejects it rather
than inventing or converting a fee. See the Saxo [precheck reference](https://www.developer.saxo/openapi/referencedocs/trade/v2/orders/post__trade__precheck/schema-iprecheckorderresponse)
and [order-activity guide](https://www.developer.saxo/openapi/learn/audit-orderactivities).
