# SD-11G — Local no-network SignalDeck ↔ SideDeck credential and proxy parity check

**For local Codex only** on the owner's Windows workstation. GitHub **cannot read** ignored `.env` files. Owner authorised an offline comparison; the original eToro one-time GET permission was **consumed** by an HTTP 403 on the SideDeck v1 search. **Do not initiate any eToro API call** from either repository, browser automation, direct PowerShell, curl, Test-NetConnection, or a model. Do not attempt authenticated read as a diagnostic; a fresh user approval is required.

## What to inspect safely

1. Locate **both actual local checkouts** (`SignalDeck` and `sidedeck`), identify the checkout folder and `Settings`/dotenv loading mechanism, **without pasting paths containing personal names into a public commit**. SignalDeck reads settings using Pydantic with `env_file=".env"`, `ETORO_API_KEY|SIGNALDECK_ETORO_API_KEY` and `ETORO_USER_KEY|SIGNALDECK_ETORO_USER_KEY`. SideDeck's live probe reads process environment and the earlier Codex run manually loaded its local `.env`.
2. Confirm by safe in-process inspection which **effective loaded values** each application would use. Compare **only** `both_present`, `same_api_key`, `same_user_key`, and `same_key_pair` as booleans. Treat both projects' environments independently: Pydantic aliases, process env overrides, quoting, hidden Unicode, and launch working directory can affect the effective key. If a value is missing, report `missing`, not its contents.
3. **Never** display, print, truncate, fingerprint, hash, persist or compare via command-line arguments or shell history the credential values, even masked prefixes. The process must never send them to CI, logs, ChatGPT, GitHub, telemetry or an LLM prompt. A test script can use in-memory equality but must remain **local and untracked**; delete nothing belonging to user. Do not trust default `repr(Settings)` output.
4. Compare only boolean `present` for environment variables `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` (both process and system settings when readable without elevation). Do not print proxy contents, hosts or authentication details. Determine offline if SignalDeck used direct `http.client.HTTPSConnection` while SideDeck uses `urllib` which may honor proxy settings. Do not alter/bypass proxy/firewall or send traffic.
5. Compare sanitized, dummy-only v1 versus legacy v2 request shape using `tests/test_etoro_request_contract.py`: official documented v1 `GET /api/v1/market-data/search?internalSymbolFull=AAPL` versus historical SignalDeck v2 `GET /api/v2/market-data/instruments/search?query=AAPL&limit=5`. Verify `Accept: application/json`, `x-api-key`, `x-user-key`, per-request UUID, HTTPS host and permitted GET only. The present `src/sidedeck/domain/etoro.py` now uses supported `desc` for candles instead of `backward`. Do not add a live v2 fallback.
6. Present a **small table of boolean presence/match findings** and analysis of plausible causes. Redact any error that includes actual key text, local usernames, file paths or proxy values. Update `TODO.md` with only boolean conclusions **after** checking whether those conclusions are appropriate to store in the owner's GitHub repo.
7. If credentials do not match, report `MISMATCH` and identify that as a potentially actionable source difference; **do not overwrite either .env or regenerate keys** without permission. If they match, treat API-version/proxy route as remaining unconfirmed hypotheses. No further network test without renewed scope.

## Stop condition

Return exactly one of `OFFLINE_PARITY_CONFIRMED`, `OFFLINE_KEY_MISMATCH`, `OFFLINE_LOAD_MISMATCH`, or `OFFLINE_COMPARISON_BLOCKED` with safe boolean results. **This check never proves that API v2 currently works or that either credential is entitled to eToro Market Data**.
