## Independent source review — correction required before owner account test

Inspected `src/sidedeck/domain/etoro.py`, `src/sidedeck/data_probe.py` and their tests at baseline. The current CI is green on synthetic mocks, but those mocks do not establish eToro wire compatibility.

**Official eToro market-data instrument lookup guide:** https://api-portal.etoro.com/guides/get-instrument-id — recommends `GET /market-data/search?internalSymbolFull=AAPL` and validating `internalSymbolFull` exactly. Current code instead sends `search=AAPL`, matches `symbol`/`ticker`, and assumes `instrumentId`, `assetType`, `exchange`, `currency` are all returned; these assumptions need source-backed normalization, never permissive defaulting.

**Published eToro-derived OpenAPI candle example:** https://apis.io/examples/etoro/getCandles-response-200/ — top-level `{"interval": "...", "candles": [{"instrumentId": 12, "candles": [{"instrumentID": 12, "fromDate": "...", "open": ..., ... , "volume": 0.0}]}]}`. Current parser reads a flat top-level `data.candles[]`, expects `timestamp|date|time` (not `fromDate`), treats a nested group as a candle, and rejects valid **zero volume**. Update the typed decoder with explicit schema checks, approved group/instrument ID match and controlled handling for no-volume/inapplicable-volume instruments. Do not infer volume where none exists.

**Critical probe mismatch:** Current `python -m sidedeck.data_probe --provider etoro --market-data-only --allow-read-network --confirm-owner-read-only` only prints `client.resolve_instrument("AAPL")`; it never invokes `fetch_daily_candles` or `scan_five_year_daily`. Thus no five-year verdict can be produced from the advertised CLI. Build a bounded four-symbol coverage workflow and save **redacted**, non-sensitive evidence.

**HTTP 429 handling:** `urllib.request.urlopen` raises `urllib.error.HTTPError` for non-2xx responses. Current `UrllibReadOnlyTransport.get` does not translate this into `(429, headers, bytes)` so `EtoroHistoricalDataClient._get` cannot apply its bounded retry policy as tested. Catch at transport boundary (avoid echoing body, keys or request URL in exceptions); implement documented `Retry-After` / bounded backoff without retry storms or repeated 401/403. Validate actual GET status flow with local fake `urlopen`.

**Five-year feasibility defect:** 1,000 OneDay bars are **incapable of containing 1,250 distinct daily sessions**; `scan_five_year_daily` cannot honestly return `PASS_5Y_DAILY` using only one 1,000-bar response. The code also uses `date(cutoff.year - 5, cutoff.month, cutoff.day)`, which can raise for Feb 29. Replace naive thresholds with an exchange-calendar-aware coverage calculation over an explicitly defined rolling five-year interval, including holidays, partial/incomplete sessions, duplicate dates, splits/adjustments and missing sessions. `INSUFFICIENT_DEPTH` must remain the result until legitimate earlier daily observations are retrieved through an actually supported paginated/dated request or an approved licensed second source. Don't quietly treat calendar weekdays as observed trading days.

**Source-specific search fields:** Published client implementations differ on whether search fields are under `items`, `results` or `data`, and instrument IDs may be `internalInstrumentId` or `instrumentId`. Verify current official reference; support only documented/versioned variants, with tests matching source samples. If asset class / leverage / currency cannot be *verified* from search payload, require separate metadata GET and fail closed until resolved; do not default missing values to EQUITY or USD.

**GET-path safety:** The transport currently forms URLs from arbitrary `path`; client methods use fixed paths, but the transport is a public callable. Allowlist strictly `/market-data/search`, the exact bounded candle URL structure, and the specific historical-closing-price GET endpoint if implemented. Reject anything under `/trading`, other hosts, path traversal, redirects off the official HTTPS domain and unexpected methods. API credentials must not be leaked to redirect destinations. Test this, including a malicious redirect.
