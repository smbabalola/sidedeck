## Confirmed research — do not overclaim

- eToro's official [Market Data product](https://builders.etoro.com/products/market-data-realtime) and [API FAQ](https://builders.etoro.com/faq) describe OHLC candles, historical closing prices, instrument search and current rates. Their API is generally free for eligible users subject to terms and rate limits, but market-data API **access and actual historical coverage for this owner have not been tested**.
- Market candle REST path is documented in eToro-derived OpenAPI listings as `GET /api/v1/market-data/instruments/{instrumentId}/history/candles/{direction}/{interval}/{candlesCount}`. **Verify exact details and current schema against the official API portal before coding.** Search ticker IDs via `GET /api/v1/market-data/search`; never assume an instrument ID.
- Independent live-tested client research (https://github.com/florinel-chis/etoro-go) reports a **1000-bar ceiling per interval**, no from/to pagination; 1000 `OneDay` bars usually cover only ~4 US trading years, **not 5 years / ~1250 sessions**. Weekly bars may cover five+ years but are **not** a replacement for five-year daily OHLCV.
- The historical closing-price endpoint `/api/v1/market-data/instruments/history/closing-price` also exists in API catalogues; investigate whether it can provide earlier daily *closes* and whether this is sufficient for any specific analysis. Do **not** assume it returns full five-year OHLCV.
- eToro market-data availability, five-year depth, volume quality, currency, adjustment policy, symbol mapping, data usage/storage rights and corporate-action handling remain **UNVERIFIED**. If eToro has <5 years of daily data, fail the 5-year acceptance gate and assess an authorised second data provider or licensed import. Do not fabricate, interpolate or backfill missing days.
- The eToro market-data endpoint is a **read** surface separate from broker orders. No user credentials were copied to GitHub. No request has been sent by ChatGPT or SideDeck so far.

## Safety and boundaries

- **Read-only historical-data adapter only** in a dedicated process. No orders, trade endpoints, eToro position/account mutations, eToro Demo execution, credential reuse by model workers, or real-money modes. Do not broaden SideDeck's allowlist (AAPL, MSFT, SPY, QQQ) just to make tests pass.
- This specification authorises coding, official documentation validation, offline mock tests, and an explicit CLI opt-in for later **market-data GET only**. It is **not a blanket approval to use keys**. Before authenticated calls, confirm from owner the eToro credential/environment and that it is permitted for read-only market-data GETs. Do not send requests merely because variables happen to exist in `.env`. Avoid exposing keys in logs.
- Never store or push API/user keys, `.env`, order IDs, private account information or full sensitive request headers. Use isolated local secrets, scoped configuration, bounded timeouts and rate limits. No writes to existing owner databases without approval; demo data goes to ignored local results/disposable DB.
- Upstream TradingAgents still may invoke Yahoo from identity, compiled tool nodes, memory/reflection even if SideDeck fetches prices elsewhere. Supplying eToro data **does not itself enforce network isolation**. The upstream graph is still blocked until verified controlled tools plus native-process-level default-deny egress exist. Never remove the isolation gate merely because the price source changed.
- eToro current-day/historical bars are not automatically usable as **true point-in-time** research evidence. Avoid look-ahead and survivorship claims, disallow yet-to-complete candles, and record how each observation became available. For historical price-only comparisons, accurately describe limitations.
